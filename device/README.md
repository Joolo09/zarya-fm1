# Сборка под FM-1 — СТАТУС: НЕ СОБИРАЛОСЬ, НЕ ПРОШИВАЛОСЬ

`zr_device.c` — черновик адаптера между ядром ZARYA и официальным SDK
[m-vave/fm1_open](https://github.com/m-vave/fm1_open) (коммит `4c7496da…`, V14).
В этой сессии компилятор pi32v2 запустить не удалось, поэтому файл **ни разу
не компилировался** и на железе не проверялся.

Что проверено чтением исходников SDK: сигнатуры `fm1.h` (экран, панель, MIDI,
Flash), номера кнопок/энкодеров, размер блока 128 кадров / 44.1 кГц / Q23.

Что НЕ проверено и должно быть сделано до любой прошивки:

1. Контракт остальных хуков, которые бинарная библиотека требует от приложения
   (`groove_project_*`, `groove_midi_*`, `groove_samples_*`, `groove_transfer_*`,
   `groove_fm_*`). Самый безопасный путь — оставить официальные `app/*.c` как
   есть и заменить только `app/screen.c` на `zr_device.c`; при линковке
   выяснится, какие функции `screen.c` ещё нужны остальным файлам.
2. Вызов `zr_device_audio(rendered)` в `app/board/audio.c` сразу после
   `fm1_engine_render(...)`, и `zr_device_sysex()` из `fm1_app_sysex` в
   `app/transfer.c`.
3. Бюджет RAM (по карте линковки) и CPU (`fm1_audio_stats_read`).
4. Формат пользовательского раздела: ZARYA и стоковая прошивка используют один
   и тот же раздел в РАЗНЫХ форматах. ZARYA ничего не пишет, пока вы сами не
   подтвердите FORMAT на устройстве, но после FORMAT стоковые проекты/сэмплы в
   этом разделе будут потеряны — сначала сделайте бэкап в официальном workbench.

Сборка официальным способом (Windows, JieLi toolchain 2.5.3) описана в README
fm1_open. Флаги для ядра: `-DZR_TARGET_FM1`.
